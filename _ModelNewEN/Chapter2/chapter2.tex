\section*{Introduction}
The design chapter is \textbf{\textsl{not always required}}. When the work is
a theoretical study or a system deployment, drawing class or sequence diagrams
is unnecessary -- often counter-productive.\\
For development work, however, design is mandatory.

\section{Recommendations}
A few general rules:
\begin{itemize}
  \item Pick a methodology -- a unified process, an agile method, etc.
\end{itemize}

\section{Diagrams}
Choose the diagrams that are relevant to your application. The use-case,
class and sequence diagrams are usually required. You may add any other
diagram you find pertinent; for a multi-tier application, for instance, the
deployment diagram is useful.
\begin{itemize}
  \item Diagrams must be clear, readable and well explained -- without
        drowning the reader in detail. Lengthy explanations get tiresome;
  \item If a diagram is too large, split it into several diagrams or abstract
        away some details. If splitting is impossible, print it on A3 and fold
        the page. The key requirement is that every label remains legible.
\end{itemize}

\subsection{Sequence Diagram}
A sequence diagram:
\begin{itemize}
  \item Represents one possible scenario inside a use case. You do not need to
        show every possible execution path;
  \item Represents the interaction between objects -- every instance in a
        sequence diagram should correspond to a class that appears in the
        class diagram;
  \item Many sequence diagrams are usually possible; pick two or three of the
        most important to include in the report (authentication is not one of
        them).
\end{itemize}

\subsection{Class Diagram}
A class diagram:
\begin{itemize}
  \item Must reflect the chosen software architecture. If you use MVC, the
        three layers should be visible in the class diagram via packages;
  \item Stereotypes are strongly encouraged. For a web application, consider
        using the stereotypes in Figure~\ref{fig:fig2}:
  \begin{figure}[!ht]\centering
    \includegraphics[scale=0.9]{stereotypes.jpg}
    \caption{Stereotypes}
    \label{fig:fig2}
  \end{figure}
  \item Don't confuse classes with database tables -- resist the temptation to
        put an \texttt{id} field everywhere.
\end{itemize}
