\section*{Introduction}
% intent: Frame the chapter as the realisation of the designed architecture
% across the full stack, consolidating Phases 0-2 by engineering theme rather
% than by phase. State the deliverable: a live pilot at clmpilot.com covering
% the contract lifecycle plus the enterprise capabilities of
% Section~\ref{sec:fr-enterprise}. Name the organising principle: each section
% is a recurring pattern that spans the stack, illustrated by the realised
% domains, never a per-tier or per-phase tour. Per the report-wide rule, the
% chapter intro must not reference other chapters.
This chapter presents the CLMPilot platform as it was actually built and
shipped. It consolidates the work delivered across
Phases~0 to~2 -- the engineering foundations, the contract-lifecycle core and
the enterprise capabilities -- and organises it by engineering theme rather
than by phase, so each section reads as one recurring pattern carried across
the stack. \emph{(Section-level skeleton; prose to follow.)}
